IBM Bob + BAW Dev Tools MCP

From a sentence or a screenshot to a running BAW app

Describe a form, a workflow or an approval process in plain English, or show Bob a picture of the screen. Bob designs it, builds it, installs it on your IBM Business Automation Workflow server and tests it in a real browser. Nobody opens Process Designer and nobody edits TWX XML by hand.

Build

New apps, from words or pictures

Bob writes a short JSON description of the app and the server turns it into a real BAW process app, with its screens made of widgets people can still drag and drop in Coach Designer.

App from a description

Plain English in, an installed app out.

  • From a request: "an office supply request with requester, item, quantity and needed-by date, a review screen, a navy header and rounded buttons."
  • From a requirements document: Bob turns its headings into a to-do list and builds one item at a time, stopping for your answer after each.
  • Design approval first: Bob shows the look, screens, fields, buttons and its assumptions, and waits for your OK.
  • Changes the same way: "add a field", "split this into tabs" or "add an approval step" edits the spec and builds a new snapshot.
  • Complete apps: business object, multi-step screens or one tabbed screen, Back, Next, Submit and Cancel, an optional review page and a confirmation page.

Screens from screenshots

Attach an image or a mockup, get BAW screens that match it.

  • Layout: tabs, sections, side-by-side columns and their relative widths, and which field sits in which column.
  • Controls: labels, text fields, text areas, dates, dropdowns, radio groups, checkboxes, required markers, help icons and buttons.
  • Look: brand colours sampled from the image, the logo cut out for the header banner, field icons, corner shapes and button placement.
  • Compare and fix: after installing, Bob screenshots the live app, compares it with the original and fixes the differences.
  • Clear about gaps: Bob lists what it guessed, such as the options of a closed dropdown, and what it can't build yet, such as tables or file uploads.

Theme and branding

One file controls the whole look.

  • Colours, font, corner shape, field icon boxes, page width, button placement, and the header's product name and logo.
  • The same theme styles the classic screens and the React + Carbon screens. Rebranding means editing one file and rebuilding.
  • Written from your description, a screenshot or a brand you name. There is no default look, so Bob asks for one.
  • An optional header banner with a title and subtitle.

Forms and fields

The building blocks of every screen.

  • Field types: text, text area, date, checkbox, whole number, decimal, dropdown, radio group, a Yes/No radio for true/false values and a number dropdown.
  • Field options: help text, required fields that block the finishing button, patterns and examples.
  • Sections: titled, with 1 to 6 columns. The title bar can be hidden.
  • Tabs: a Next button per tab, an option to keep users on a tab until its required fields are filled, and the first tab with an error selected for you.
  • Save as Draft on tabbed workflow tasks. The task returns to the inbox and reopens on the tab where it was saved.
  • Two business objects in one app, for example Group and Quote edited side by side.

Reusable field groups

Build a block of fields once, place it on any screen.

  • Reusable by default: every section becomes a View listed under the app's User Interface in Workflow Center.
  • One group, many places: editable on the form, read-only on a later step and shown on the review page.
  • Suggested by Bob when three or more fields repeat on two or more screens, and built only after you agree.
  • Preview service for each group, so you can view it on its own.
  • Per-placement settings: hide any optional field, or set the whole placement to Read only.
  • Edits made in BAW are kept: if someone changes a group in Coach Designer, a rebuild keeps their version, says what changed and asks before replacing it.

Workflow

A real BPMN process behind the form

One line in the request, "add an approval by Underwriting", produces this process. It is saved as a BPMN 2 model, so it opens in Business Automation Studio's process editor, where people can keep moving, adding and connecting steps by hand.

Quote WorkflowGenerated by create_app from the spec's process section
Sequence flowSend Back loop, repeats until approved

What the workflow can include

  • Swim lanes such as Sales and Underwriting, with the form as the first task.
  • Approval task with Approve, Send Back and an "Approved?" decision.
  • Review task as an alternative: everything read-only, with an Edit button on each section that unlocks it in place.
  • Rewired processes: when an app is modernized, its processes are switched to the modern screens.

How you change it

  • Through chat: "rename the lanes", "add an approval step" or "switch to a review step". Bob edits the spec and rebuilds.
  • By hand: open the process in Business Automation Studio's process editor.
  • Tested end to end: Bob works every task of the process in a browser until it completes.

Free-form BPMN modelling, drawing any process from scratch, is outside this tool. Bob refers that to a separate IBM BAW Author mode.

Modernize

Existing apps, a modern UI

Bob gives a legacy app new React + Carbon screens while the logic underneath keeps running exactly as before.

Legacy to React + Carbon

New screens on top, the old logic untouched underneath.

  • Inventory: Bob reads every screen of an existing app (sections, fields, buttons, flow and groups) into an editable spec.
  • Improve: better labels, grouping, required fields, patterns, examples and help text, then a pause for your review.
  • Modern UI: a React + IBM Carbon copy of each service, built from drag-and-drop widgets and styled by the theme file.
  • Nothing breaks: the original flow, scripts, variables and button wiring keep running, and the classic screens stay in the app.
  • Event code carries over from the old controls to the new widgets.
  • Hand-made screens: for a screen that needs a custom design, Bob writes a dedicated React + Carbon screen.

Drag-and-drop widget toolkits

Generated screens stay editable by people.

  • App Builder Widgets for new apps, and Modernizer Widgets, 12 React + Carbon widgets for modernized apps. The server builds and installs both.
  • Editable in Coach Designer, with palette icons and live previews on the canvas.
  • Familiar settings: each Modernizer Widget has the same settings, sections and events as the IBM UI Toolkit control it replaces.
  • New widgets when needed, such as a Yes/No toggle. Bob writes the component and its icon, checks it in a browser and publishes a new toolkit version.

Run

Data, servers and testing

Everything after the build: the app's data, getting it onto the server safely, and proof that it works.

Database

The platform's PostgreSQL, with safety rails.

  • Explore: list databases and tables, describe columns, keys and indexes, and answer questions with SQL.
  • Data apps: an app can Load a record by key and Save on Submit. Bob creates the table, checks its shape, installs the app and tests both actions.
  • Import and export: load CSV or JSON files into tables, and export tables or query results to CSV.
  • Limited by design: Bob's login writes only to the app database, with caps on rows, size and time. A change to a system database needs your approval and backs up the affected rows first. Only you can run a restore.
baw-database skillAny mode

Install and versions

Safe, traceable releases on your server.

  • Browse: process apps, toolkits, snapshots and launchable services with their run URLs.
  • Move apps: export an app to .twx, or install one and wait for the result.
  • Safe versioning: every build is a new snapshot, reusing a snapshot name is refused, and there is no delete tool.
  • Older BAW: packaging for 24.0.x and 25.0.x, checked against exports from those versions. Installs on them are not tested yet.
  • No server needed to build: you still get .twx files to import yourself.

Testing in a real browser

Proof that the app works, with screenshots.

  • Screens: opens the service, screenshots every screen, fills in sample values or yours, and presses the buttons you name.
  • Tabs: opens, fills and screenshots every tab.
  • Required fields: confirms that Submit stays blocked while they are empty.
  • Whole workflows: starts the process and works every task until it completes, including paths such as "Send Back once".
  • Drafts: saves a draft, reopens the task and checks that the values were kept and that it opens on the right tab.

Working with Bob

Two specialist modes, with you in control.

  • BAW App Builder builds new apps and changes existing ones. BAW Coach Modernizer modernizes their screens.
  • Automatic routing: ask for "a React UI" and Bob moves to the Modernizer. Ask for a new field and it moves back. Data questions work in any mode.
  • Human in the loop: Bob asks before it builds, crops images, installs or changes a system database.
  • Guardrails: Bob can only edit app specs, themes and UI files, credentials never reach the AI, and database rows are treated as data, never as instructions.

What you need

  • IBM Bob, or any MCP client that runs a local (stdio) server.
  • A BAW server on Cloud Pak for Business Automation, with an account that can install process apps. Without one, the build tools still produce files to import.
  • Python 3.11+ with uv, Node.js 18+ and a Chromium-based browser for the tests.
  • Optional: PostgreSQL admin settings for the database tools.

Not covered yet

  • Table controls and file uploads on generated screens.
  • Free-form BPMN modelling beyond form, approval and review workflows.
  • Changing or removing an existing widget during a build. That is a code change, made separately.
  • Deleting apps or snapshots. There is no delete tool.
