Export and import BAW apps from the terminal

A step-by-step guide for downloading a process app snapshot as a .twx file and installing a .twx file, using only curl and the BAW REST API. No MCP server, Bob skills or project scripts needed.

CP4BA · BAW 26.0.0 curl + jq macOS · Linux · WSL Export: read-only Import: changes the server 8 October 2026

Which endpoints these are and why →

The whole journey

Every request to BAW needs two passes: a login token that proves who you are, and a CSRF token that BAW asks for on every REST call. Once you have both, exporting is two lookups and a download, and importing is an upload and a status check.

Run every step in the same terminal window.

Each step saves values such as $TOKEN in the terminal session, and later steps use them. If you close the window, start again from step 2.

Before you start

A terminal

macOS: the Terminal app. Linux: any shell. Windows: use WSL (Ubuntu) or Git Bash; the commands are written for bash and zsh, not PowerShell.

Your BAW address

The Cloud Pak URL you open in the browser, up to the first / after the host, for example https://cpd-cp4ba.apps.example.com.

An account that can install

Your Cloud Pak username plus either its password or a Cloud Pak API key. Exporting needs read access to the app; importing needs BAW author rights.

To create an API key, sign in to the Cloud Pak console, open the user menu at the top right, choose Profile and settings, then API key → Generate new key. Copy it somewhere safe; it is shown once.

Part 1 · Log in

1Check your tools

You need curl (sends web requests) and jq (reads JSON answers). Run:

curl --version | head -1
jq --version

Each line should print a version. If jq is missing, install it with brew install jq on macOS or sudo apt install jq on Ubuntu and WSL.

2Tell the terminal your server and user

Replace the two example values with yours. The password line hides what you type, so it never appears on screen or in your shell history.

export BAW_URL="https://cpd-cp4ba.apps.example.com"
export BAW_USER="your-username"
printf 'Password: '; read -s BAW_PASSWORD; echo

Using an API key instead? Replace the last line with:

printf 'API key: '; read -s BAW_APIKEY; echo
About -k in every command.

Test clusters such as TechZone use self-signed certificates, so the commands pass -k to skip the certificate check. On a production server, remove -k and point curl at your company's certificate with --cacert ca.pem instead.

3Get a login token

This asks Cloud Pak for a token that proves who you are. Use the command that matches step 2.

With a password:

TOKEN=$(curl -sk -X POST "$BAW_URL/icp4d-api/v1/authorize" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg u "$BAW_USER" --arg p "$BAW_PASSWORD" '{username: $u, password: $p}')" \
  | jq -r .token)

With an API key:

TOKEN=$(curl -sk -X POST "$BAW_URL/icp4d-api/v1/authorize" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg u "$BAW_USER" --arg k "$BAW_APIKEY" '{username: $u, api_key: $k}')" \
  | jq -r .token)

Check it worked without printing the token itself:

echo "token length: ${#TOKEN}"
Expected

A length in the thousands (about 3,300 on our test cluster). A length of 4 means the token is the word null: the username, password or URL is wrong.

4Get a CSRF token

BAW wants a second token, sent in a header called BPMCSRFToken, on every REST call. It lasts up to two hours (7200 seconds).

CSRF=$(curl -sk -X POST "$BAW_URL/bas/ops/system/login" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"refresh_groups": false, "requested_lifetime": 7200}' \
  | jq -r .csrf_token)
echo "csrf length: ${#CSRF}"

Expect a length around 110. Now save both tokens as one shortcut, so later commands stay short:

AUTH=(-H "Authorization: Bearer $TOKEN" -H "BPMCSRFToken: $CSRF")

Every command below uses "${AUTH[@]}", which expands to those two headers.

Part 2 · Export an app

Exporting only reads from the server. It is safe to repeat.

5Find the app's acronym

BAW identifies a process app by a short acronym, such as ZZGQ3, not by its display name. List all process apps with both:

curl -sk "${AUTH[@]}" -H "Accept: application/json" \
  "$BAW_URL/bas/ops/std/bpm/containers?type=PA" \
  | jq -r '.containers[] | select(.archived | not) | "\(.container)\t\(.container_name)"'

Example output (first column is the acronym):

ZZGQ3	ZZ Generate Quote
ZZPNE	ZZ Pharmacy Network Enrollment

Save the one you want:

APP="ZZGQ3"

6Find the snapshot

A snapshot is a saved version of the app. List them, oldest first:

curl -sk "${AUTH[@]}" -H "Accept: application/json" \
  "$BAW_URL/bas/ops/std/bpm/containers/$APP/versions" \
  | jq -r '.versions | sort_by(.creation_date)[] | select(.archived | not) | "\(.version)\t\(.version_name)\t\(.creation_date)"'
1.0.0	1.0.0	2026-10-08T18:24:03z
1.1.0-react	1.1.0-react	2026-10-08T18:33:51z

The first column is the snapshot acronym that the export needs. It is often the same as the name in the second column, but not always, so always copy the first column.

SNAP="1.1.0-react"

Or pick the newest snapshot automatically:

SNAP=$(curl -sk "${AUTH[@]}" -H "Accept: application/json" \
  "$BAW_URL/bas/ops/std/bpm/containers/$APP/versions" \
  | jq -r '[.versions[] | select(.archived | not)] | sort_by(.creation_date) | last | .version')
echo "$SNAP"

7Download the .twx

curl -sk "${AUTH[@]}" -H "Accept: application/octet-stream" \
  -o "$APP-$SNAP.twx" \
  -w "HTTP %{http_code}, %{size_download} bytes\n" \
  "$BAW_URL/bas/ops/std/bpm/containers/$APP/versions/$SNAP/export"
Expected

HTTP 200 and a size in megabytes (about 15 MB for a small app, because the file carries its toolkits). The file is saved in the folder you are in; pwd shows which one.

To leave out the system toolkits (System Data, UI Toolkit), which every server already has, add ?format=twxWithoutToolkits to the URL. The file is much smaller and imports the same way on a server with the same BAW version. This project's create_app exports a base app this way.

The Accept header matters.

The export answers HTTP 406 if the request asks for JSON. Keep Accept: application/octet-stream on this command. If the HTTP code is not 200, the saved file contains an error message instead of the app: cat "$APP-$SNAP.twx" shows it.

A .twx is a zip file. To check it is real:

unzip -l "$APP-$SNAP.twx" | tail -1

This prints a file count such as 17 files. If you see "End-of-central-directory signature not found", the download was an error message; read it with cat.

Part 3 · Import (install) an app

Importing changes the server and cannot be undone from the terminal.

It adds the app, or a new snapshot of an existing app, to BAW. Practise on a test server with an app whose name you recognise as a demo (our team uses names starting with ZZ). Removing a snapshot afterwards needs an administrator.

A .twx built by this project's create_app or generate_app.py imports the same way, with these steps or in Workflow Center (Process Apps, Import).

8Check what the file will install

The app and snapshot a .twx installs into are written inside the file, not chosen at upload time. Look before you upload:

FILE="ZZGQ3-1.1.0-react.twx"
TARGET=$(unzip -p "$FILE" META-INF/package.xml | sed -n '/<target>/,/<\/target>/p')
echo "App name:    $(echo "$TARGET" | sed -n 's/.*<project [^>]* name="\([^"]*\)".*/\1/p')"
echo "App acronym: $(echo "$TARGET" | sed -n 's/.*<project [^>]*shortName="\([^"]*\)".*/\1/p')"
echo "Snapshot:    $(echo "$TARGET" | sed -n 's/.*<snapshot [^>]* name="\([^"]*\)".*/\1/p')"
App name:    ZZ Generate Quote
App acronym: ZZGQ3
Snapshot:    1.1.0-react

The first line keeps only the file's <target> section, so the toolkits the app depends on are not mixed in. This file installs app ZZGQ3 (ZZ Generate Quote), snapshot 1.1.0-react.

9Check the snapshot name is new

If that snapshot already exists on the server, BAW keeps the old content and your upload changes nothing. Check first, using the acronym from step 8:

curl -sk "${AUTH[@]}" -H "Accept: application/json" \
  "$BAW_URL/bas/ops/std/bpm/containers/ZZGQ3/versions" \
  | jq -r '.versions[] | .version_name'
  • The name from step 8 is not in the list: go ahead.
  • The name is in the list: stop. The file needs a new snapshot name, which you set in Workflow Center (or with this project's tools) before exporting again.
  • The answer is an error CWTBG0624E … does not exist: the app is not on this server yet, so the import creates it. Go ahead.

10Upload the .twx

The file goes up as a form field that must be named install_file.

QUEUE_URL=$(curl -sk -X POST "${AUTH[@]}" -H "Accept: application/json" \
  -F "install_file=@$FILE;type=application/octet-stream" \
  "$BAW_URL/bas/ops/std/bpm/containers/install" \
  | jq -r .url)
echo "${QUEUE_URL%%\?*}"

BAW answers right away with HTTP 202 and a status address, then installs in the background. The echo shows the address without its private key, for example …/bas/ops/system/queue/142. If it prints null, the upload was refused; run the command again without | jq -r .url to read the error.

11Wait for the result

Ask the status address every 5 seconds until the state is success or failure. The first line rebuilds the address on your own BAW URL, in case the server reports an internal host name.

STATUS_URL="$BAW_URL/bas/ops${QUEUE_URL#*/ops}"
while true; do
  STATE=$(curl -sk "${AUTH[@]}" -H "Accept: application/json" "$STATUS_URL" | jq -r .state)
  echo "$(date +%T)  $STATE"
  case "$STATE" in pending|running) sleep 5 ;; *) break ;; esac
done

A small app usually finishes within a few minutes. Then read the details:

curl -sk "${AUTH[@]}" -H "Accept: application/json" "$STATUS_URL" | jq '{state, result}'
StateMeaning
pending · runningStill installing. The loop keeps waiting.
successInstalled. Go to step 12.
failureNot installed. result holds the reason. CWTBG0737E is a general server error: the file is damaged or not a BAW export, or an administrator must check the server log.

The status stays available for at least 48 hours, so you can check it again later.

12Confirm and clean up

The new snapshot should now be listed:

curl -sk "${AUTH[@]}" -H "Accept: application/json" \
  "$BAW_URL/bas/ops/std/bpm/containers/ZZGQ3/versions" \
  | jq -r '.versions[] | "\(.version_name)\t\(.creation_date)"'

Optional: list the services you can open in the browser, with their run URLs. This call uses an older BAW REST API that is not in the API explorer, but it is the one that returns run URLs.

curl -sk -H "Authorization: Bearer $TOKEN" -H "Accept: application/json" \
  "$BAW_URL/bas/rest/bpm/wle/v1/exposed/service" \
  | jq -r '.data.exposedItemsList[] | select(.processAppAcronym == "ZZGQ3" and .tip) | "\(.display)\t\(.runURL)"'

When you are done, remove the secrets from the terminal session:

unset BAW_PASSWORD BAW_APIKEY TOKEN CSRF AUTH QUEUE_URL STATUS_URL

When something goes wrong

What you seeLikely causeFix
Token length 4 in step 3Wrong username, password, API key or URLCheck the values from step 2. The URL has no path after the host.
HTTP 401 on any stepMissing or expired login tokenRepeat steps 3 and 4. Tokens expire, so long sessions need a fresh login.
HTTP 403Your account lacks rights for that app or actionAsk an administrator for access to the app, or author rights for imports.
CWTBG0624E: Container '…' does not existWrong acronym, or the app is not on this serverCopy the acronym from step 5. Acronyms are case-sensitive.
CWTBG0011E: The mandatory parameter … is not specifiedA required part of the request is missingCopy the command again; the full URL and its ?type= part matter.
HTTP 406 on exportThe request asked for JSONUse Accept: application/octet-stream on the export.
curl: (60) SSL certificate problemSelf-signed certificateOn a test server, keep -k. On production, use --cacert.
jq: command not foundjq is not installedSee step 1.
jq: … Cannot iterate over nullBAW answered with an error instead of a listRun the same curl without the | jq … part to read the error.
Install ends in failureDamaged file, not a BAW export, or a server-side problemRe-check step 7 and step 8 on the file, then ask an administrator to read the server log.
Install succeeds but nothing changedThe snapshot name already existedSee step 9. Give the snapshot a new name and export again.

All in one: copy-paste scripts

The same steps as two short scripts. Save each as a file, make it runnable with chmod +x baw-export.sh, and set BAW_URL, BAW_USER and BAW_PASSWORD (or BAW_APIKEY) as in step 2 before running.

baw-export.sh read-only

#!/usr/bin/env bash
# Usage: ./baw-export.sh APP [SNAPSHOT]   (newest snapshot when SNAPSHOT is left out)
set -euo pipefail
APP="$1"; SNAP="${2:-}"
BAW_URL="${BAW_URL%/}"
if [ -n "${BAW_PASSWORD:-}" ]; then
  BODY=$(jq -n --arg u "$BAW_USER" --arg p "$BAW_PASSWORD" '{username: $u, password: $p}')
else
  BODY=$(jq -n --arg u "$BAW_USER" --arg k "$BAW_APIKEY" '{username: $u, api_key: $k}')
fi
TOKEN=$(curl -sk -X POST "$BAW_URL/icp4d-api/v1/authorize" -H "Content-Type: application/json" -d "$BODY" | jq -r .token)
[ "$TOKEN" != null ] || { echo "Login failed"; exit 1; }
CSRF=$(curl -sk -X POST "$BAW_URL/bas/ops/system/login" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"refresh_groups": false, "requested_lifetime": 7200}' | jq -r .csrf_token)
AUTH=(-H "Authorization: Bearer $TOKEN" -H "BPMCSRFToken: $CSRF")
if [ -z "$SNAP" ]; then
  SNAP=$(curl -sk "${AUTH[@]}" -H "Accept: application/json" "$BAW_URL/bas/ops/std/bpm/containers/$APP/versions" \
    | jq -r '[.versions[] | select(.archived | not)] | sort_by(.creation_date) | last | .version')
fi
CODE=$(curl -sk "${AUTH[@]}" -H "Accept: application/octet-stream" -o "$APP-$SNAP.twx" -w "%{http_code}" \
  "$BAW_URL/bas/ops/std/bpm/containers/$APP/versions/$SNAP/export")
[ "$CODE" = 200 ] || { echo "Export failed (HTTP $CODE):"; cat "$APP-$SNAP.twx"; echo; rm -f "$APP-$SNAP.twx"; exit 1; }
echo "Saved $APP-$SNAP.twx"

baw-import.sh changes the server

#!/usr/bin/env bash
# Usage: ./baw-import.sh FILE.twx
set -euo pipefail
FILE="$1"
BAW_URL="${BAW_URL%/}"
PKG=$(unzip -p "$FILE" META-INF/package.xml)
TARGET=$(sed -n '/<target>/,/<\/target>/p' <<<"$PKG")   # this app, not its toolkits
APP=$(sed -n 's/.*<project [^>]*shortName="\([^"]*\)".*/\1/p' <<<"$TARGET")
SNAP=$(sed -n 's/.*<snapshot [^>]* name="\([^"]*\)".*/\1/p' <<<"$TARGET")
[ -n "$APP" ] && [ -n "$SNAP" ] || { echo "$FILE does not look like a BAW export"; exit 1; }
echo "This file installs app $APP, snapshot $SNAP."
if [ -n "${BAW_PASSWORD:-}" ]; then
  BODY=$(jq -n --arg u "$BAW_USER" --arg p "$BAW_PASSWORD" '{username: $u, password: $p}')
else
  BODY=$(jq -n --arg u "$BAW_USER" --arg k "$BAW_APIKEY" '{username: $u, api_key: $k}')
fi
TOKEN=$(curl -sk -X POST "$BAW_URL/icp4d-api/v1/authorize" -H "Content-Type: application/json" -d "$BODY" | jq -r .token)
[ "$TOKEN" != null ] || { echo "Login failed"; exit 1; }
CSRF=$(curl -sk -X POST "$BAW_URL/bas/ops/system/login" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"refresh_groups": false, "requested_lifetime": 7200}' | jq -r .csrf_token)
AUTH=(-H "Authorization: Bearer $TOKEN" -H "BPMCSRFToken: $CSRF")
if curl -sk "${AUTH[@]}" -H "Accept: application/json" "$BAW_URL/bas/ops/std/bpm/containers/$APP/versions" \
   | jq -e --arg s "$SNAP" '.versions // [] | any(.version_name == $s or .version == $s)' >/dev/null; then
  echo "Snapshot $SNAP already exists in $APP; BAW would keep the old content. Stopping."; exit 1
fi
read -r -p "Install it? Type yes to continue: " OK; [ "$OK" = yes ] || exit 1
QUEUE_URL=$(curl -sk -X POST "${AUTH[@]}" -H "Accept: application/json" \
  -F "install_file=@$FILE;type=application/octet-stream" "$BAW_URL/bas/ops/std/bpm/containers/install" | jq -r .url)
[ "$QUEUE_URL" != null ] || { echo "Upload refused"; exit 1; }
STATUS_URL="$BAW_URL/bas/ops${QUEUE_URL#*/ops}"
while true; do
  RESULT=$(curl -sk "${AUTH[@]}" -H "Accept: application/json" "$STATUS_URL")
  STATE=$(jq -r .state <<<"$RESULT"); echo "$(date +%T)  $STATE"
  case "$STATE" in pending|running) sleep 5 ;; *) break ;; esac
done
jq '{state, result}' <<<"$RESULT"
[ "$STATE" = success ]

Commands checked on 8 October 2026 against BAW 26.0.0 on Cloud Pak for Business Automation (TechZone). Login, CSRF, listing, export and the status check ran as shown. The upload and status loop were checked with a deliberately invalid file, which the server rejected with failure, so no app was changed.
