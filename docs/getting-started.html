Get started with BAW Dev Tools MCP

From a fresh laptop to your first app running on BAW, built by IBM Bob. Follow the steps in order; each one ends with a check so you know it worked before moving on.

New teammates macOS · Linux Python 3.11+ · Node 18+ · uv IBM Bob About 30 minutes 9 October 2026

Where you will end up

  • The project on your laptop, connected to a BAW test server.
  • IBM Bob showing the baw-dev-tools MCP server with 13 tools and two modes: 🏗️ BAW App Builder and ✨ BAW Coach Modernizer.
  • A small ZZ app you asked Bob for, installed on the server, tested in a browser, with a link you can open.

Steps

1Get access to a BAW test server

Ask your team lead or BAW admin for:

A user namejsmithThe user must be allowed to install process apps

To make an API key: log in to the Cloud Pak console, open your profile menu at the top right, choose Profile and settings, then API key → Generate new key. Copy it straight into step 4; the console shows it only once.

Check: you can log in to the Cloud Pak console in a browser with that user.

2Install the tools

Open a terminal and check what you already have:

git --version
uv --version
python3 --version
node --version

Check: all four commands print a version, Python is 3.11 or newer and Node is v18 or newer.

3Get the code

git clone https://github.com/unclethien/baw-bob-dev-tools-mcp.git
cd baw-bob-dev-tools-mcp

Stay in this folder for every step below.

Check: ls baw_mcp.py prints baw_mcp.py.

4Add your server settings

Copy the template and make it readable only by you:

cp .env.example .env
chmod 600 .env

Open .env in an editor (open -e .env on macOS, or nano .env) and fill it in:

SettingValue
BAW_URLThe base URL from step 1, e.g. https://cpd-cp4ba.apps.<cluster>
BAW_USERYour user name
BAW_PASSWORDYour password, or leave it empty and set:
BAW_APIKEYYour Platform API key. Used only when BAW_PASSWORD is empty
Keep .env to yourself

It holds your credentials. Git ignores it, so it is never committed; do not copy it into chat, tickets or screenshots. The MCP server reads it, logs in and never returns your credentials to the agent.

Check: ls -l .env starts with -rw-------.

5Install the screen tools

The React screens and the browser tests have their own packages:

(cd react-coach && npm install)

Check: it ends with "added … packages" and no ERR! lines.

6Check the connection

List the apps on the server, using the same code the MCP server uses:

python3 baw_ops.py list

Each line is an acronym, app or toolkit, and the name:

HSS        app      Hiring Sample
HSSX2      app      Smart Hire

Check: you see a list of apps. If you see an error instead, look at its last line:

Last line saysFix
Missing BAW settings: …A setting in .env is empty; the message names it
HTTP Error 401Wrong user, password or API key. Try logging in to the console with them
nodename nor servname providedThe host name in BAW_URL is wrong, or you need the VPN. On Linux it reads Name or service not known
HTTP Error 500Usually BAW_URL has a path after the host name, such as /bas/bpm; remove it
timed outIt waits a long time, then fails: the server is not reachable from your network. Check the VPN

7Check the Hiring Sample

The tools package every new app using the Hiring Sample (HSS) as a base, so it must be on the server:

python3 baw_ops.py list | grep '^HSS '

Check: one line, HSS app Hiring Sample. If nothing prints, ask your BAW admin to install the Hiring Sample; it ships with BAW.

8Connect Bob

Bob starts the MCP server from .bob/mcp.json, which needs the full path to this folder. This command writes it for you from the example:

sed "s#/ABSOLUTE/PATH/TO/baw-bob-dev-tools-mcp#$PWD#" .bob/mcp.example.json > .bob/mcp.json
grep baw_mcp.py .bob/mcp.json

The second line should show your real path ending in /baw_mcp.py. Then start the server once by hand; the first run downloads its packages, so Bob does not time out waiting for them later:

uv run --quiet --script baw_mcp.py < /dev/null && echo "Server starts"

Now open this folder as the workspace in Bob and open Bob's MCP panel.

Check: baw-dev-tools shows as connected with 13 tools:

9Build your first app

In Bob, switch to the 🏗️ BAW App Builder mode and send:

Build a small ZZ app for an office supply request: one step with requester name,
item, quantity and needed-by date, then a review screen. Install it and test it.

What Bob does, and where you come in:

  1. Reads the server (list_apps) to pick a ZZ acronym nobody uses.
  2. Writes the app spec to work/<ACRONYM>.app.json. You can open it; the app spec reference explains every key.
  3. Calls create_app. Approve it. It builds the .twx in work/. The first build also saves the Hiring Sample to work/base-HSS.twx.
  4. Checks the screens with inspect_coaches.
  5. Calls install_app. Approve it. The install usually takes one to three minutes.
  6. Runs test_service: a headless browser opens each screen, fills sample values and presses Next.
  7. Reports the app, acronym, snapshot, run URL and the screenshot folder.

Check: Bob's report includes a run URL and says the test passed ("ok": true).

Have a screenshot of a form instead? Save it in work/ and ask: "Build a ZZ app whose screen looks like work/my-form.png. Install it, test it and compare the result with the screenshot." Bob then uses the screenshot-to-app skill, which also copies the colours, header and layout.

10Look at the result and change it

  • Run it: open the run URL in a browser where you are logged in to the Cloud Pak console.
  • Screenshots: work/shots-<ACRONYM>-…/ has one picture per screen from the test.
  • Change it: ask Bob, e.g. "Add a cost centre dropdown with 100, 200 and 300, then install and test again." Bob edits the spec and bumps app.snapshot, because every install needs a new snapshot name. The run URL stays the same.
  • Give it a modern UI: switch to ✨ BAW Coach Modernizer and ask Bob to modernize the app. It writes React + Carbon screens and installs them as another snapshot.

Check: the app opens, and the screens match the screenshots.

Good to know

The rules the tools follow

  • Only apps whose name starts with "ZZ" and whose acronym starts with ZZ can be installed.
  • A snapshot name can be used once per app; reusing it is refused, because BAW would silently keep the old content.
  • There is no delete tool. To remove a test app, ask a BAW admin to archive it.
  • Tools only read and write files inside this folder. Bob edits only work/, app-specs/ and react-coach/src/screens/.

Use another browser

The browser test tries BROWSER_PATH first, then Brave, then Chrome. To use another Chromium browser with Bob, add it to the server's environment in .bob/mcp.json:

"env": { "BROWSER_PATH": "/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" }

The same "env" block can hold BAW_URL to point Bob at another server without editing .env; settings in the environment win over .env.

Other MCP clients

Any MCP client that runs stdio servers works. Give it this command, with your full path:

{ "command": "uv", "args": ["run", "--quiet", "--script", "/ABSOLUTE/PATH/TO/baw_mcp.py"] }

The Bob modes and skills live in .bob/; other clients get the tools, but not the step-by-step skills.

Build an app without an agent

For a new app you can run the same build from the terminal. Copy an example, change its app.name and app.acronym to an unused ZZ name, then:

cp app-specs/example-equipment-request.json work/ZZOFFICE.app.json
# edit work/ZZOFFICE.app.json: "name": "ZZ Office Request", "acronym": "ZZOFFICE"
python3 generate_app.py work/ZZOFFICE.app.json work/ZZOFFICE-1.0.0.twx
python3 baw_ops.py install work/ZZOFFICE-1.0.0.twx
python3 baw_ops.py services ZZOFFICE
The scripts skip the guard rails

baw_ops.py install does not check the ZZ name or the snapshot name; only the MCP tools do. And for a new snapshot of an app that already exists, use create_app: it reuses the installed app's identity, which generate_app.py alone does not. To install by hand with curl, follow the terminal guide, which includes those checks.
