Before the meeting Thirty minutes before

  1. Check the login file (.env) has the BAW and PostgreSQL settings. Never show it on screen.
  2. Get the latest project (git switch main && git pull). Open it in Bob; the tools panel shows baw-dev-tools with 21 tools. If it shows fewer, restart baw-dev-tools in that panel.
  3. Put the sample spreadsheet where Bob can read it, and start from an empty table, so Bob creates it live. The table holds only sample data.
  4. Keep the App Builder Widgets build in work/ (ABW-1.0.4.twx).
  5. Pick a new acronym for the app (the script uses ZZQDB; use ZZQDB2 after a rehearsal). ZZGWQ and ZZQDBR are taken.
  6. In Bob's auto-approve settings, keep change_system_db off, so Bob must ask. Act 4 relies on it.
  7. Open a spreadsheet program (Excel or Numbers) and a browser tab for BAW.
  8. In Bob, pick the 🏗️ BAW App Builder mode. Make the font bigger.
  9. Do one full rehearsal, so you know how long each step takes. Then repeat step 3 and pick a new acronym.
  10. Afterwards, ask a BAW admin to archive the test app: Bob cannot delete apps.

Safety ruleWhy it matters

A change to a system database asks a person first, and backs up firstNothing changes there without a decision and a way back
Bob uses its own limited loginThe admin password never reaches Bob or the screen
A load is all or nothingA bad spreadsheet never half-loads
Every question and change has a time limit and a size limitBob can't slow the platform down
The app's Load and Save run fixed statementsNobody can make the app run their own SQL
Where is our data?
On the platform's own database server, in the database set aside for app data. Not on this laptop, and not inside Bob.
Can Bob see our passwords?
No. The connector keeps them; Bob works through a limited login made for it.
Can Bob break BAW?
Its login can only read BAW's databases. A change there needs a person's approval, and a backup is taken first.
Does Bob ask before every change to the app database?
Not by default, because it's where we test. That's a setting: in production, turn on asking for those tools too.
Can we use our existing tables?
Yes. Bob reads a table's columns and builds the form from them.
Who can use Load and Save?
Anyone signed in to BAW who can open the app, like any other service in it.
How much data?
A spreadsheet up to 100 MB per load; answers up to 1,000 rows; exports up to 200 MB.
Other databases, such as Oracle or Db2?
Today, PostgreSQL only.
Does the modern React screen save too?
Not yet. Load and Save are in the classic screens today.
