IBM Bob × BAW Dev Tools MCP

Screenshots in. Working BAW app out.

A one-hour demo. IBM Bob, an AI assistant, turns pictures of an old screen into a working BAW app with an approval workflow, then gives it a modern look. First how it works, then the live demo.

Before the meeting.

Thirty minutes before: Bob connected, the pictures in place, one rehearsal done.

  1. Check the BAW login file (.env) is filled in. Never show it on screen.
  2. Open the project in Bob. The tools panel shows baw-dev-tools with 14 tools.
  3. Put the six pictures of the old screen and the client's newer quote screen generate-quote.png in screenshots/Quote/, and nothing else. It stays on this laptop.
  4. Do one full rehearsal. Open Business Automation Studio in a second tab.
  5. In Bob, pick the BAW App Builder role and allow mode switches in Bob's auto-approve settings. Make the font bigger.

06:00 / 12:00

What Bob can do.

Fourteen tools in four groups, and two specialist roles.2

Bob's tools
Look at BAWSee which apps and versions exist, and download one.
Look at picturesOpen a screenshot, read its exact colours, cut out a part such as a logo.
BuildTurn a description into an app, read an app back into a description, build the modern screens.
Run on BAWInstall an app, and test it in a real browser by clicking through every screen.
Bob's two roles
🏗️ BAW App BuilderTurns a request or pictures into a working app, with a workflow if needed.
✨ BAW Coach ModernizerGives an existing app a modern look, as a new copy next to the old one.
“Most tools only look. The ones that change something ask first. Bob stops to show the design, and again before it installs. When the job changes, it switches role by itself.”

12:00 / 15:00

How to ask Bob.

Describe the result, not the steps. Bob picks its own tools.

  1. What you want"Build a ZZ app".
  2. What to work fromThe files, by name. Bob opens them itself.
  3. What Bob cannot seeLike pictures that overlap.
  4. How it should lookLayout, colours and rules, in users' words. Demo 2 adds this.
  5. How far to goInstall and test, or "show me first". Answer a stop with "Approved."

Demo 1. Rebuild the old screen.

Pictures of an old CRM screen in, a working BAW app out, then a two-step approval workflow.

Do Flip through the six pictures: one long quote screen in an old CRM, captured while scrolling. Point at the drop-downs, checkboxes and the rewards list.

Bob does Nothing yet. Let the room look at the old screen.

“This screen lives in an old CRM. All we have is pictures of it.”

Do Paste request 1. When Bob stops, scroll through its design and answer “Approved.”

Bob does Opens each picture, reads the sections, columns and drop-downs, reads the colours, then stops to show the design.

“We did not list any fields or colours. The pictures are the requirement.”

Do Say yes when Bob asks to install. Show its test picture next to the originals.

Bob does Builds the app, asks before installing, then clicks through it in a real browser, compares it with the pictures and fixes any difference.

“Nothing reaches BAW until a person says yes. Then Bob checks its own work: about 60 fields in 7 sections, same layout, same colours.”

Do Paste request 2 and approve. While it runs, open the app in Business Automation Studio, then Processes: the two lanes and the send-back path. Drag a box to show it can be edited.

Bob does Adds the workflow, stops to show the steps, asks before installing, then runs it once: fill, send back, fill again, approve.

“This is a normal BAW workflow, not a picture. Our developers can open it and change it.”

Demo 2. A modern version.

Show generate-quote.png, the client's newer screen they already like: tabs, four columns, buttons bottom right. Then ask Bob to match it.

Bob does Switches to its second role by itself, reads the client's screen and its blue, plans the tabs and columns, improves labels and checks, then stops to show the plan.

Say “Bob changed role by itself. Only the screen changes; the process behind it stays the same.”

Bob does Builds the modern screen as a new copy next to the old one, asks before installing, then tests it in a browser. Run it in Studio: leave a required field empty to show the check.

Say “The layout is the client's own newer screen. The old screen is still there, so nothing is lost.”

Bob does Adds the rules to the screen, asks before installing, tests it. Pick “Other” and watch its box appear; press Submit with a field empty and watch it jump to the right tab.

Say “Business rules, one per line, in users' words. They react instantly, and the data lands in the same place in BAW.”

48:00 / 52:00

Safety, and the questions you will get.

Asks before changing your appsYour existing apps stay as they are unless you say yes.
Every install is a new versionNothing is overwritten; you can always go back.
No delete toolBob cannot remove anything.
The password stays in the connectorBob never sees it.
A person approves every changeBob stops before building and before installing.2
Does Bob write the BAW code itself?

No. It writes a short description; the connector builds the app from standard BAW parts.

Is the workflow real?

Yes. It opens in Studio like any other BAW process, and developers can change it.

Can it read from or save to a database?

Not yet. That is the next step, and it needs a database connection set up on the BAW server.

What can it not build from a picture yet?

Tables, file uploads, links and extra buttons. Bob lists them and offers to add them in the modern screen.

Does it work with our existing apps?

It can read any app and describe it. It only installs into test copies.

Can other AI assistants use it?

Yes. The connector follows the open MCP standard, so any assistant that supports MCP can use the same 14 tools.1

What happens when something goes wrong?

Bob gets a plain error message, fixes its description, and tries again.

Bob's tools panel shows 0 toolsRestart baw-dev-tools in that panel.
“Login failed”Check the login file off screen; switch to the rehearsal app meanwhile.
“Version already exists”Let Bob pick the next version number: a safety rule working.
Fields need attentionA required field was empty; Bob adds sample values and tries again.
A slow installTalk through the diagram while it runs.
