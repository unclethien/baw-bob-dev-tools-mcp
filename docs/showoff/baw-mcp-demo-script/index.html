Guardrails, and the questions you will get.

Installs only into ZZ appsDemo work can never touch a real app.
Every install is a new snapshotReusing a name makes BAW silently keep the old content.
No delete toolThe agent cannot remove anything.
Credentials stay in the serverBob never sees a password or a token.
A person approves every changeBob asks before create, modernize and install, and edits only its own folders.2
Does Bob write BAW XML?

No. It writes JSON specs and React files. The server generates the TWX.

Is the BPMN a real process?

Yes. Bob generates a business process with lanes: the form is the first task, then a review task with Approve and Send Back. It opens in Studio’s process editor, where developers add steps, timers or a team per lane.

Can it read from or save to a database?

Not yet. BAW reads and writes databases through its SQL services and a JDBC data source on the server. Loading a record into the form and saving it on submit is the next step, and it needs a data source to use.

What can it not build from a screenshot yet?

Tables, file uploads, links and extra buttons. Bob lists them and offers to add them in a React screen.

Does it work with our existing apps?

Read-only, yes. export_app and inspect_coaches turn any app into a coach spec. Output installs only into ZZ copies.

Can other agents use it?

Yes. It is a standard stdio MCP server, so any MCP client can call the same 14 tools.1

What happens when something fails?

Errors come back as plain messages, such as a failed login or a compiler error with file and line. Bob fixes the input and retries.
