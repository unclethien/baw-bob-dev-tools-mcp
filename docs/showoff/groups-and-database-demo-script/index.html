The timings are tight. If Bob runs long in Act 1 or Act 2, shorten Act 3 to the spreadsheet and one Load. This script joins reusable groups and the Quote screen remembers into one story on one app.

Before the meeting Thirty minutes before

  1. Check the login file (.env) has the BAW and PostgreSQL settings. Never show it on screen.
  2. Get the latest project (git switch main && git pull). Open it in Bob; the tools panel shows baw-dev-tools with 21 tools. If it shows fewer, restart baw-dev-tools in that panel.
  3. Make sure the Toggle does not exist yet, and start from an empty table, so Bob creates both live. After a rehearsal, reset both. The table holds only sample and test quotes.
  4. Keep screenshots/Quote/ as it is: the six pictures of the old screen (image (1).png to image (6).png) and the client's newer quote screen (generate-quote.png). It stays on this laptop and is never published.
  5. Keep only the two toolkit builds in work/ (ABW-1.0.4.twx and the newest MDW-*.twx), so Bob reads nothing from earlier runs.
  6. Pick a new acronym and put it in the Act 1 request (the script uses ZZGDB; use ZZGDB2 after a rehearsal). Names already used on the test server:
    • Apps: ZZQI, ZZLGQ, ZZLGQI, ZZSLX, ZZGRP, ZZGRP2, ZZGWQ, ZZLGG, ZZGQ3, ZZGDEMO, ZZGDBR, ZZQDBR
    • App Builder Widgets (ABW): up to 1.0.4
    • Modernizer Widgets (MDW): up to 2.1.0, so Bob's new widget goes into 2.2.0 or later
  7. In Bob's auto-approve settings, allow mode switches, and keep change_system_db off, so Bob must ask. Act 4 relies on it.
  8. Open Workflow Center (Business Automation Studio) in a second browser tab, a terminal, and a spreadsheet program (Excel or Numbers).
  9. In Bob, pick the 🏗️ BAW App Builder mode. Make the font bigger.
  10. Do one full rehearsal, so you know how long each step takes. Then repeat step 3 and pick a new acronym. Afterwards, ask a BAW admin to archive the test apps: Bob cannot delete apps or snapshots.

Bob builds every screen from small widgets, combines them into reusable groups, and saves the form to the database set aside for app data.

Safety, questions and next steps.

0 of 10 checks passed

Safety ruleWhy it matters
A person approves every design, plan and installBob stops before building and before installing
Every install is a new versionNothing is overwritten; you can always go back
Bob adds widgets, never changes existing ones, and tests a new one firstApps that depend on a widget keep working; a broken widget never reaches BAW
Bob writes only in the app databaseBAW's own records and the other products' databases are read only for its login
A change to a system database asks a person first, and backs up firstNothing changes there without a decision and a way back
A load is all or nothingA bad spreadsheet never half-loads
The app's Load and Save run fixed statementsNobody can make the app run their own SQL
Passwords stay in the connectorBob never sees them
Can smaller widgets be combined into larger reusable ones, keeping configuration and data binding?
Yes. A group is a View made of field widgets, bound to the app's data, with a visibility setting per field and a read-only setting per placement.13 Groups inside groups, and repeating groups (lists), are not built yet.
Which changes can we make in BAW, and which need Bob?
Changes to a group's fields are yours: on its next rebuild Bob keeps your version and asks before replacing it. Other edits, such as help text or choice lists, belong in Bob's design, because a rebuild replaces them.4
Can a group be shared across apps?
Not yet: groups live in one app. Widgets are shared, through the toolkit.
Where is our data?
On the platform's own database server, in the app database. Not on this laptop, and not inside Bob.
Can Bob break BAW?
Its login can only read BAW's databases. A change there needs a person's approval, and a backup is taken first.
Does Bob ask before every change to the app database?
Not by default, because it's where we test. That's a setting: in production, turn on asking for those tools too.
Does the modern screen load saved quotes?
Not yet. It saves on Submit; Load is on the classic screen.
Other databases, such as Oracle or Db2?
Today, PostgreSQL only.
Can other AI assistants do this?
Yes. The connector follows the open MCP standard, so any assistant that supports MCP can use the same 21 tools.6
